# Mini Framework

A tiny, zero-dependency JavaScript framework with Vue-inspired single-file components, reactive data, and client-side routing. No build tools, no npm, no bundler — just files in a browser.

---

## How it works

Three core pieces:

**`lib/framework.js`** — Parses and runs components. Each component is an HTML file with three blocks: `<template>` (markup), `<script>` (data and logic), and `<style>` (scoped CSS). Data is made reactive via Proxy — any assignment to `this.data` triggers a re-render automatically.

**`lib/router.js`** — Handles URL-based navigation without page reloads. On startup it fetches `lib/manifest.json` to load routes, intercepts link clicks and `popstate` events, matches the URL to a route, and swaps the component into `#app` with a fade transition.

**`serve.js`** — Dev server. On startup it scans `pages/` recursively, generates `lib/manifest.json`, and watches for new or deleted page files to regenerate it. Serves real files on disk directly; falls back to `index.html` for SPA routes that don't exist as files.

## Directory structure

```
/
├── index.html              # Shell — mounts navbar, footer, and #app
├── serve.js                # Dev server — node serve.js
├── lib/
│   ├── framework.js        # Component parser, reactivity, directives
│   ├── router.js           # Router, Store, meta tags
│   └── manifest.json       # Auto-generated by serve.js — do not edit
├── pages/
│   ├── index.html          # → /
│   ├── about.html          # → /about
│   ├── blog.html           # → /blog
│   └── blog/
│       └── [slug].html     # → /blog/:slug
├── components/
│   ├── navbar.html         # Persistent shell navbar
│   ├── footer.html         # Persistent shell footer
│   └── layout.html         # Layout wrapper with <slot>
└── data/
    └── posts.json
```

## Running locally

```bash
node serve.js
```

Opens `http://localhost:3100` automatically. Terminal prints all discovered routes:

```
  ✓ manifest.json — 4 routes
    /                              → ./pages/index.html
    /about                         → ./pages/about.html
    /blog                          → ./pages/blog.html
    /blog/:slug                    → ./pages/blog/[slug].html
```

No manual route registration needed. Drop a file in `pages/` and restart.

## Adding pages

**Static page** — create `pages/pricing.html` → available at `/pricing`.

**Dynamic route** — create `pages/blog/[slug].html` → available at `/blog/:slug`. The bracket name becomes the param name. Nest for multiple segments: `pages/shop/[category]/[id].html` → `/shop/:category/:id`.

**Nav link** — add a comment anywhere in the file:

```html
<!-- nav: Pricing -->
```

The router picks this up and includes it in the navbar's link list.

## Components

```html
<template>
    <div>
        <h1>{{ title }}</h1>
        <button @click="increment">Clicked {{ count }} times</button>
        <ul>
            <li v-for="item in items">{{ item.name }}</li>
        </ul>
    </div>
</template>

<script>
({
    data() {
        return {
            title: 'Hello',
            count: 0,
            items: []
        }
    },
    methods: {
        increment() {
            this.data.count++;
        }
    },
    async mounted() {
        const res = await fetch('/data/items.json');
        this.data.items = await res.json();
    }
})
</script>

<style>
h1 { color: navy; }
</style>
```

- `<script>` must return a plain object wrapped in `({...})`.
- `data()` should be a function so each instance gets its own state.
- Setting `this.data.anything = value` re-renders automatically.
- `mounted()` can be async — runs once after first render.

## Directives

| Directive | What it does | Example |
|---|---|---|
| `{{ expr }}` | Renders a value | `{{ post.title }}` |
| `v-if` | Shows/hides element | `<div v-if="loading">` |
| `v-for` | Repeats element | `<li v-for="post in posts">` |
| `v-model` | Two-way input binding | `<input v-model="query">` |
| `:class` | Conditional classes | `<div :class="{ active: isOpen }">` |
| `@click` | Click handler | `<button @click="save">` |

## Routing

Routes load automatically from `lib/manifest.json`. No manual registration.

**Navigate via link:**
```html
<a href="/blog">Go to blog</a>
```

**Navigate programmatically:**
```javascript
this.data.$router.push('/blog/my-post');
```

**Read route params:**
```javascript
async mounted() {
    const slug = this.data.$route.params.slug;
    const posts = await fetch('/data/posts.json').then(r => r.json());
    this.data.post = posts.find(p => p.slug === slug);
}
```

## Navbar and active links

The router writes nav links to `$store` after every navigation. Navbar reads them from localStorage so it works as a persistent shell component:

```javascript
data() {
    const raw = localStorage.getItem('mini-fw:$nav');
    return { links: raw ? JSON.parse(raw) : [] }
}
```

Template:
```html
<li v-for="link in links">
    <a href="{{link.href}}" class="nav-link {{link.active}}">{{link.label}}</a>
</li>
```

Active class is computed by the router on every navigation. Add `<!-- nav: Label -->` to a page to include it.

## Persistent shell components

Components outside `#app` persist across navigations. Register them so the router re-renders them after each route change:

```javascript
parseSFC('/components/navbar.html').then(c => {
    c.render(document.querySelector('[data-component="navbar"]'));
    router.registerComponent(c, '/components/navbar.html');
});
```

## SEO / Meta tags

Static meta:
```javascript
({
    meta: {
        title:       'About — My Site',
        description: 'Learn more.',
        image:       'https://mysite.com/og/about.png',
        siteName:    'My Site',
        twitterCard: 'summary_large_image',
    },
    data() { return {} }
})
```

Dynamic meta (blog post):
```javascript
({
    meta() {
        return {
            title: `${this.data.post?.title} — My Site`,
            description: this.data.post?.excerpt,
            type: 'article',
        }
    },
    data() { return { post: null } }
})
```

Supported keys: `title`, `description`, `image`, `imageAlt`, `imageWidth`, `imageHeight`, `url`, `canonical`, `type`, `siteName`, `locale`, `twitterCard`, `twitterSite`, `twitterCreator`, `author`, `robots`, `article`.

Covers: Google, Open Graph (Facebook/LinkedIn/Discord/Slack/WhatsApp), Twitter/X cards.

## State — `$store`

localStorage-backed store injected into every component:

```javascript
this.data.$store.set('user', { name: 'Alice' });
const user = this.data.$store.get('user', null);   // second arg is fallback

// Fetch with TTL caching (5 min default)
const posts = await this.data.$store.fetch('/data/posts.json');
const fresh = await this.data.$store.fetch('/data/posts.json', { force: true });
```

---

## posts.json format

```json
[
    {
        "title":    "Getting Started",
        "author":   "Your Name",
        "date":     "January 1, 2025",
        "category": "Guide",
        "excerpt":  "Short summary for the listing page.",
        "content":  "Full post body for the individual post page."
    }
]
```

`slug` is generated automatically from `title` — don't add it manually.

## Changelog

### Current
- **Auto route discovery** — `serve.js` scans `pages/` and writes `lib/manifest.json` at startup. Restart the server after adding a page and it's registered automatically.
- **Nuxt-style dynamic routes** — `pages/blog/[slug].html` → `/blog/:slug`. Bracket in the filename becomes the URL param.
- **Nav label via comment** — `<!-- nav: Home -->` in any page file adds it to the navbar list.
- **`router.init()` is async** — fetches the manifest before the first navigation so routes are ready immediately.
- **Smarter file server** — `serve.js` serves any file that exists on disk directly (components, assets, manifest), and only falls back to `index.html` for paths with no matching file.

### Store + fetch caching
- Replaced `$globalState` / `$componentState` with a single `Store` class backed by localStorage with namespaced keys.
- Added `$store.fetch(url, { ttl, force })` — caches API responses in localStorage so repeat navigations are instant without re-fetching.

### Persistent navbar + active routes
- Navbar moved outside `#app` in the shell so it survives navigations without re-mounting.
- Router re-parses and re-renders registered shell components after every route change so the active class updates correctly.
- Router writes nav links to `$store` — navbar reads them. Adding a nav item = adding one route with a `nav` label.

### Props + slots
- Vue-style `props` with type coercion (`String`, `Boolean`, `Number`) and defaults.
- Props available as first-class reactive values — `{{ title }}` not `{{ $props.title }}`.
- `<slot>` support for layout components with full nested component resolution.

### SEO meta tags
- `applyMeta()` runs after every navigation and updates `<head>` tags.
- Covers standard SEO, Open Graph, and Twitter/X cards from a single config object.
- `type: 'article'` support with `article:published_time`, `article:tag` etc.

### v1
- Single-file components: `<template>`, `<script>`, `<style>`.
- Reactive data via `Proxy`.
- Directives: `{{ }}`, `v-if`, `v-for`, `v-model`, `:class`, `@click`.
- Client-side router with dynamic segments — routes were registered **manually** in `router.js` as a hardcoded array:
  ```javascript
  const router = new Router([
      { path: '/',           component: './pages/index.html' },
      { path: '/about',      component: './pages/about.html' },
      { path: '/blog',       component: './pages/blog.html' },
      { path: '/blog/:slug', component: './pages/blog-post.html' }
  ]);
  ```
- Dynamic route pages used a flat naming convention — `pages/blog-post.html` for `/blog/:slug`, not a folder/bracket structure.
- No manifest file — adding a route meant editing `router.js` directly.
- Live reload dev server — `serve.js` was a simple static file server with no page scanning.
